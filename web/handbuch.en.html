Welcome

PS5 Cooling & System Center - Pro is a homebrew program (ELF) for a jailbroken PS5. It controls the fan according to a calm, freely adjustable target temperature and comes with a web interface that you open from any device on your home network: phone, tablet, PC or the console's own browser. On top of that come game management, packages, saved data, a file manager, payloads, profile and system information.

Quiet, not loudThe control holds a target temperature – gently and slowly, without constant ups and downs.
Everything in the browserNo installation on a PC needed: open the address, done.
No internetThe app only connects to programs on the console and to the browsers on your home network.
Safe to useDeleting and power commands require a confirmation; important things are protected.
Tested on a PS5 Pro (CFI-7021) with firmware 12.00. Other firmware may work but has not been checked.
2

Requirements

  • A PS5 with a jailbreak and a loaded payload loader (elfldr, port 9021).
  • kstuff must be loaded – only with it can the app reach the fan controller. Without kstuff, the display and the web interface work, but fan control then reports “not available”.
  • A device with a browser on the same home network.
  • To send the ELF, a program such as nc (netcat) or a payload sender of your choice.
3

Installation & first start

  1. Send PS5_Cooling_System_Center_v1.67.0.elf to the console, port 9021, e.g.:
    nc -q0 <PS5-IP> 9021 < PS5_Cooling_System_Center_v1.67.0.elf
  2. A notification with the address of the web interface appears at the top left of the TV.
  3. Open it in the browser: http://<PS5-IP>:8086/

The tile on the Home screen

On the first start, the app itself creates a tile under “Media”. It only opens the web interface – it does not start the program. So after every restart of the console, the ELF has to be sent once again.

Only ever run one instance. Two instances control the fan at the same time and interfere with each other. You can stop an old instance on the “Payloads” page; otherwise a restart helps.
Tile deleted, or want a new tile picture? Delete the tile on the console (Options button, Delete) and on the “System” page press Install tile.

The starter tile: starting without sending

With the starter tile the ELF no longer has to be sent. Unpack PPSA86921.zip from the release and copy the folder PPSA86921 to /data/homebrew/ (over FTP or with the file manager). ShadowMountPlus adds a tile for it.

  • One tap on the tile starts the app if it is not running yet and then opens the web interface in the console's browser. If the app is already running, it only opens the interface.
  • The app is part of the tile's eboot.bin. After an update, copy the folder from the new release, otherwise the tile starts the old version.
  • ShadowMountPlus is needed for it. The old media tile (above) may stay or be deleted.

The interface at a glance

On the left is the sidebar with the sections Profile, Games, Files, Payloads, Cooling, System, Log and Credits. At the top in the header, on every page: the power options, “Fullscreen”, “Expert mode” and the connection indicator.

Power options

Rest Mode, Restart, Turn off and Safe Mode. Every command needs two clicks: the first turns the button yellow (“Really? Click again”) and states the consequence, the second carries it out. A double click does not count; after ten seconds the button returns to normal.

When turning off or restarting, unsaved game progress is lost.

Language

At the top right of the header you choose the language of the interface: Deutsch, English, Italiano, Español, Français or Русский. On the first visit, the page uses your browser's language; if that is not available, English. The browser remembers the choice; the page then reloads and stays on the section you were on. Numbers, dates and times follow the language.

Notifications that the console itself shows on the TV (at start or with a warning) are in German.

Manual and FAQ

Under “Credits” in the sidebar, Manual and FAQ open these texts directly in the app, in the chosen language (without the screenshots, so that the app stays small). With pictures, both are available as PDF and HTML for download with every release.

Windows and the right stick

When a window opens (e.g. for deleting), the background is dimmed and stays still. In the PS5's browser, the right stick then only scrolls the window itself.

Controller keys

In the console's browser four buttons help: L1 and R1 go to the previous and next page of the sidebar, L2 and R2 scroll the page up and down. The browser reports them to the page as the keys F5 to F8; they do not reload the page.

5

Cooling

The most important page: the status in plain words, the current temperature, the fan and the running game. Right below, you set the Target temperature and the Operating mode.

Target temperature

The temperature the console should hold: adjustable from 60 to 91 °C, 66 °C by default. Higher means quieter and warmer. Quick select sets the target immediately: Cool 62 °C, Balanced 77 °C, Quiet 91 °C.

91 °C is the value the console sets itself (ShadowMountPlus also offers it as the highest target): the fan stays as quiet as without the app, but the console gets noticeably warmer. The emergency limit is always at least 4 °C above the target (so 95 °C at 91 °C); the app's warning threshold moves with the target (never lower than target + 2 °C), so that it does not warn all the time with a high target; the value set in the settings stays saved.

Operating mode

Quiet, Balanced and Cool determine how strongly the fan responds to heat – they do not change the target. “Quiet” is recommended.

How the control works

  • It works with a moving average, not with single readings.
  • Within ±1 °C of the target, nothing happens.
  • The trend counts: if the temperature is already falling, the fan is not turned up any further.
  • It turns up in small steps, and turns down only once the temperature has been stably low.
  • Above the safety limit, only the hardware counts; the firmware always protects itself in addition.

Automatic mode

If “Automatic mode” is off, the app hands control back to the PS5 and only shows values. If the app is not running, the console controls the fan itself again anyway.

Display via the mute button

Press the controller's mute button twice quickly: the processor temperature and fan speed appear at the top left (without a sound) – even without the web interface. The microphone is toggled twice in the process and ends up as it was before.

The fan is a drawn speedometer: the needle shows the measured value from left (0 %) to right (100 %) and moves smoothly to every new reading; the rainbow arc lights up only as far as the needle. Needle, number and glowing edge go from blue through green and yellow to red (grey without a reading).

6

Games

The games on your Home screen with cover, format and actions. You can search by title, title ID or content ID; filter by PS5, PS4 or “Backport · AMPR · PlayGo”; and sort by Home screen order, name, play time, size and more.

Starting and closing

  • Start starts the game directly. In the console's browser, the browser closes at once when you tap, before the game loads, so that the game is in front. If the console has something to say (a refusal, an offer “Start”), it shows it as a notification at the top right.
  • If another game is already running, the app starts nothing and tells you so. Close game closes the running game immediately and without asking – anything not saved is lost.
  • A game is never started twice; a second click within 30 seconds does nothing.

Copying, moving, converting

Dump folders can be copied, moved and converted directly on the console into ffpfsc (compressed, recommended), ffpkg or exFAT – either playable in the folder homebrew of the destination (ShadowMountPlus finds it there) or as a backup in PS5-Sicherung/Spiele. Every copy is read back after writing and verified; nothing is overwritten.

Please recreate .ffpkg images made with versions before 1.48.0 (old structure).

PS4 games from USB (PS4Mount)

The tab PS4 from USB on the games page plays PS4 games (fake PKG) straight from the USB drive without installing them. It is based on PS4Mount by gasb07 (GPL-3.0), whose source code has been taken into the app.

  1. Prepare. On an exFAT drive, put the game, its update and add-ons as .pkg in the top level (or in folders named in the settings). The file names do not matter.
  2. Switch on. The switch “Switch on” starts the search; it stays on across a restart of the app. “Search now” starts a search at once.
  3. Wait. The first time, the app sorts the packages into ps4/CUSAxxxxx/ (app.pkg, patch.pkg, addcont/…) and reports each game as soon as it is ready to play. The game appears on the home screen with its icon.
  • The PKG files stay on the drive; only small management files go to the console. Deleting a game on the console or with “Remove from library” only removes it from the library, the PKG stays.
  • Updates (patch.pkg) and add-ons (DLC) are included; add-ons only when the switch in the settings is on.
  • The app has to be running for the games to stay visible after a console restart. If PS4Mount is already loaded as a payload of its own (ps4mount.elf), the switch has no effect until that one is stopped (both use port 9032).
  • Firmware (since PS4Mount 0.4.4): from 6.00 the console registers the games the usual way (tested on 13.20, reported on 6.50); below 6.00 one at a time, and where that function is missing no games are added, to protect the database. The notification at switch-on names the way. This version inside the app has been checked on a PS5 Pro with 12.00: PS4 games from a USB drive are added and run. It is switched off until you switch it on.

AMPR index, APR-EMU, PlayGo and history

Every game card has the button LZ4 asset packs … under Convert. It opens a window with tools around APR-EMU. For now it holds the AMPR index.

  • The AMPR index (ampr_emu.index) is the list of all of the game's files that APR-EMU needs to find them. The window shows whether there is one and how many files it knows.
  • Build / Rebuild creates it. For a dump folder this happens directly; for an image, ShadowMountPlus briefly mounts it for writing and unmounts it afterwards. An old index stays as ampr_emu.index.bak.
  • When converting a dump folder there is the box Build the AMPR index first (already ticked for games with APR-EMU). This puts the index inside the image – for a compressed image (.ffpfsc) it is the only way, as nothing can be written there afterwards.
A running game and any other job of the app block building. The layout follows drakmor's script build_ampr_index.py (GPL-3.0) and was compared byte for byte with its result.

APR-EMU in the game

The row APR-EMU in the game shows which libSceAmpr.sprx a game loads and lets you choose a version and put it in, bring the game's original back or remove the file. The versions are files in /data/PS5-Cooling-Center/AMPR_EMU, named like drakmor's releases (libSceAmpr.sprx-0.4.2.1-test-pack). Five versions are bundled with the app: they show in the list even when they are not in the folder yet, and get there when you build one in or with Put the bundled versions into the folder (the folder is made when needed). Add more with Add file. Every file is checked (SELF header, the mark “[AMPR_EMU]”). Variants with “pack” in the name can read LZ4 packs, “debug” writes a log.

  • Where the file goes follows ShadowMountPlus (1.7beta1 and newer): it looks first in the backport folder <scan path>/backports/<title id>/, then in the game, and the first folder that exists counts alone. For a game folder, .exfat or .ffpkg it goes to fakelib/libSceAmpr.sprx in the game (an image is briefly mounted for writing by ShadowMountPlus). A compressed .ffpfsc cannot be written: a backport folder is made there and the game stays untouched; because it hides the game's fakelib, its files are copied in. If a backport folder already exists, it is used for every format.
  • The file the game brought itself is kept once as libSceAmpr.sprx.orig and never overwritten; an earlier APR-EMU does not count as an original. Restore original puts it back. Remove deletes only the APR-EMU file.
  • The window warns when a fakelib2 lies beside fakelib (ShadowMountPlus from 1.7beta1 then reads only that one), and when ShadowMountPlus replaces the file at the start of a game from /data/shadowmount/emus (update_emulators=1). A game in LZ4 packs accepts only versions with “pack” and cannot otherwise be changed.

LZ4 asset packs (short version)

The step-by-step guide with troubleshooting is in the chapter LZ4 asset packs: step by step. Only a game that links libSceAmpr can be packed; otherwise the button is locked.

The row LZ4 asset packs packs the data of a game into seekable LZ4 packs (ampr_assets-NNN.pak, directory ampr_assets.index) that APR-EMU reads while you play and unpacks block by block. The game then takes up less space. It only works for games that are a folder (turn an image into a folder first with Unpack into a folder) and only for games that use APR-EMU: the app puts the APR-EMU version “0.4.2.1 test-pack” into fakelib (the game's own file is kept as .orig), because only the “pack” versions read packs.

The settings window (Pack with LZ4 …) asks three things:

  • How strongly? Level 3 (LZ4 Fast, quick), 9 (LZ4 HC, balanced) or 12 (LZ4 HC, smallest).
  • What goes in? Automatic: game data is packed; programs (eboot.bin, .sprx/.prx), sce_sys, fakelib, saved data and media that is already compressed (mp4, ogg, wem …) stay loose, and so do very large files that hardly compress. Or an own profile (TOML) in the format of drakmor's ampr_pack.py ([pack], [groups.NAME], [[rule]] with include/exclude, block_size, layout, compress/store/loose, [runtime]; lists for include_from lie beside it). Profiles live in the folder /data/PS5-Cooling-Center/LZ4_Profile or in the folder LZ4_Profile of a USB drive; Add profile … uploads a file there. Programs, system folders and the packs themselves always stay loose, even with a profile. Before the start the window shows how many files will be packed.
  • What happens to the originals? Pack in the game folder: the AMPR index is built afresh, the files are packed, every file is compared byte for byte with its original and only then is the original removed; on any error the packs are removed again and everything stays as before. Or as a new folder <name>-lz4 beside the game: the original stays untouched, the loose files are copied and read back.

A packed game carries the tag LZ4 packed on its card. The row then offers Check packs (every block is read, unpacked and checked against its checksum) and Unpack LZ4 … (writes the files back, compares them with the packs and then removes the packs). While a game is packed, the AMPR index is locked and the APR-EMU can only be swapped for another “pack” version: the packs belong to exactly this index.

The app keeps packing at low priority even if the window is closed; a running game must be closed first. Format (AMPRPAK4/AMPRDAT3) and rules follow drakmor's ampr_emu (GPL-3.0); packing and checking are tested against its Python tool in both directions. Files a game reads through mmap do not belong in packs – the automatic selection therefore leaves programs and system files out.

PlayGo in the game

The row PlayGo in the game works the same way for libScePlayGo.sprx, drakmor's PlayGo stub (pgo_stub, GPL-3.0): it reports everything as completely installed to a game whose PlayGo content cannot be found (any more). It only helps with games that treat PlayGo content as missing. The versions are files in the folder /data/PS5-Cooling-Center/PlayGo (libScePlayGo.sprx-0.6-nolog, libScePlayGo.sprx-0.6-log); both 0.6 builds come with the app, and “log” writes /app0/playlgo.log into the game. Each file is checked (SELF header, mark “playgo_stub.dat”). Place, the backup as libScePlayGo.sprx.orig, the backport folder for a .ffpfsc, the warnings and removing work as with the APR-EMU file; LZ4 packs play no part for PlayGo. The two files of a game can be changed independently of each other. A stub in the emulator folder of ShadowMountPlus (/data/shadowmount/emus/libScePlayGo.sprx) wins here too.

Check, unpack, repair an image

If the game is an image (.exfat, .ffpkg or .ffpfsc), the same window has three more tools. The app reads the image itself, without mounting it; a running game and any other job of the app block them.

  • Check image: for an .ffpfsc the whole container is read first (header, block table, every block unpacked – every block carries a checksum), then the files in it are checked to lie where the file system says. For .exfat and .ffpkg every file is read in full (a drive that is going bad shows there). If the check finds something, the window names the affected files, with the place where it starts. The result stays in the window until the app restarts.
  • Unpack into a folder: writes all files to homebrew/<name of the image> on a drive of your choice. Beforehand the window shows files, size, room and file system of every drive (FAT32 takes no files over 4 GB). Each file is written into a folder ending in .ps5cc-teil, read back from the drive and compared with what came from the image (CRC-32). Only when everything matches does the folder get its name; on an error or a cancel it is removed again. The image stays untouched; the game then exists twice.
  • Repair: only where it is safe. If the size of an .ffpfsc file does not match the image's header, but the data is complete and the extra bytes are empty, the app sets the size right and reads the container in full once more. Damaged blocks cannot be made again from the image alone. Repair is locked while ShadowMountPlus has the image mounted.

History

On the games page the History tab lists all of the app's jobs – copy, move, convert, split package, install, delete, file manager, saved data and AMPR index – with result (done, failed, cancelled), size, duration and time. The last 500 are kept on the console in /data/PS5-Cooling-Center/history.jsonl. Clear history deletes them (click twice).

Game plugins

The row Game plugins keeps drakmor's replacement modules in the game's fakelib folder up to date: the PlayGo stub (libScePlayGo.sprx, pgo_stub 0.6) and the DLC modules (libSceAppContent.sprx, libSceGameUpdate.sprx, libSceNpEntitlementAccess.sprx, dlc_emu 0.3) that show the DLC listed in the game's dlc_emu.ini as owned.

  • An older build (the app knows it by its checksum) is replaced, the old file stays as .old. A file of an unknown build is left alone.
  • The PlayGo stub is never added to a game that has none; that is done in the row “PlayGo in the game”. The DLC modules are only added when the game folder holds a dlc_emu.ini (without it they would hide the real DLC).
  • If a library lacks the execute permission (the app created them like that until 13 Oct 2026), “Update” sets it. Without it the console does not load it (“mount flag / attribute error”).
  • If the game has a fakelib2 or ShadowMountPlus reads a backport folder, the app changes nothing.

LZ4 asset packs: step by step

An asset pack is a few files (ampr_assets-000.pak and more, plus ampr_assets.index). The app packs a game's data into them and shrinks it with LZ4. APR-EMU reads them while you play and unpacks each block only when the game needs it. According to the developer (drakmor, ampr_emu) this halves the space and often loads 30 to 40 percent faster. Version 0.4.2.1 is expressly a test version: not every game tolerates it.

What you need

  • The game is a folder. Turn an image into a folder first with Unpack to a folder.
  • The game links libSceAmpr. The app looks for the name in eboot.bin and in sce_module and shows ✓ loads libSceAmpr itself. If it says ✗ does not load libSceAmpr itself, the button is locked: the game would not find its files in the packs. Such games can only be compressed to an .ffpfsc image (button Convert).
  • A current ShadowMountPlus, with images mounted read-only (the default).
  • Space: when packing inside the game folder the app needs about half of the game data extra until the originals are removed.

Step by step

  1. Install APR-EMU. In the window LZ4 asset packs & APR-EMU, under APR-EMU in the game, choose version 0.4.2.1 test-pack. Only versions with “pack” in the name read packs.
  2. Test unpacked. Start the game and play for a while: menu, a level, load a save. If it does not run like this, it will never run packed. Then only an older APR-EMU (for example 0.3.6.6) or none helps.
  3. Pack. Pack with LZ4 …, to begin with level 9 and Automatic. The box “started unpacked, and it ran” belongs to it. Pack in the game folder saves the most space; the originals are removed only once every file has been compared byte for byte with the packs, and on any error everything stays as before. The choice As a new folder … next to it leaves the original untouched but puts two folders with the same title ID side by side. ShadowMountPlus can choke on that and keep re-mounting the game every few seconds; take the original out of the search path first.
  4. Verify the packs. Reads every block, unpacks it and compares with the CRC file. This shows that the packs are intact, not that the game uses them correctly.
  5. Start and play. Only now you see whether it runs. Play for longer than a few seconds: menu, a level, loading and saving.
  6. If it does not run: Unpack LZ4 … writes all files back, compares them and removes the packs.

What “Automatic” leaves loose

With the profile Automatic, these stay loose: programs and libraries (eboot.bin, .prx, .sprx), sce_sys, sce_module, fakelib, saves, already compressed media (mp4, webm, ogg, wem …), configuration and data files (.json, .xml, .dat, .bin, .utoc), archives (.zip, .7z, .rar) and the game's own .pak files, the folders trophy2, uds, _DUPLEX_, decrypted and movie folders, Wwise sound banks (soundbank…, wem…), files directly in the game folder and very large files that hardly pack. This is the list that has proved itself in tools that run on the console (exFAT2AMPR by V-10, Lazy_AMPR). A profile of your own (TOML) packs what its rules say.

If the game does not start or crashes

  • First find out who is to blame. Unpack the game and start it unpacked with the same APR-EMU version. Example Arkanoid (12 Oct 2026): with 0.4.2.1 it crashed even unpacked, with 0.3.6.6 it ran. Packs were not possible there.
  • “mount flag / attribute error” in the ShadowMountPlus log: the library cannot be loaded because it lacks the execute permission (mode 0644). The app creates it with 0755. If you copied the file yourself, run SITE CHMOD 755 over FTP.
  • It crashes after a few seconds although it ran unpacked: the game probably reads files the packs do not serve, above all through mmap (mapped into memory) or for writing. Such files must stay loose. Use your own profile (TOML, folder LZ4_Profile) and add a loose rule for the file at the end: the last matching rule wins. Which files the game could not open is written by the debug version (0.4.2.1 test-debug-pack) as apr.pack.open.fail in ampr_emu.log.
  • “Automatic” is only a start. It only knows what is on the disk. Profiles made from recordings of a real play session are more reliable (ampr_pack_profile.py from ampr_emu, MkPFS).

Better than “Automatic”: the recording

“Automatic” only knows what is on the disk. A profile made from a real play session is more reliable. The row Optimization by recording does that in four steps:

  1. Start recording. The app puts the debug APR-EMU (0.4.2.1 test-debug-pack) into a folder fakelib2 of the game and copies the other libraries over from fakelib (ShadowMountPlus then reads only fakelib2 and replaces nothing in it). Requirements: the game loads libSceAmpr, the AMPR index is built, it is not in packs.
  2. Play. Start the game, play for a while (menu, a level, loading a save) and quit it normally. The game writes ampr_commands.bin. The debug version is slower.
  3. Collect the session. The app copies the recording and its index to /data/PS5-Cooling-Center/traces/<title ID>/<n>/. The debug APR-EMU empties the recording at every launch, so collect after each session. Several sessions (other levels, other modes) make a better profile.
  4. Create the profile. All sessions become <title ID>-mitschnitt.toml in the folder LZ4_Profile. For every file read it fixes the block size (16 KiB to 1 MiB), the layout (random, mixed, streaming), “hot” and the treatment (media are stored, not packed) and sets the caches of the APR-EMU. Files the game never read stay loose. When packing, choose it under Own profile.

Then Stop recording: that removes fakelib2 again. A recording only shows what was read in the scenes you played; add rules of your own for the rest.

Limits and notes

  • APR-EMU rejects sets with more than 2,000,000 files, 16,000,000 blocks or 1,024 pack files. For big games the app uses larger blocks.
  • The index, .runtime and packs of a game belong together (same build ID). Never swap single parts and change nothing while the game runs.
  • According to its author APR-EMU 0.4.2.1 still has a crash with saves. Keep the original until you have played long enough.
  • While a game is packed, the AMPR index and the APR-EMU version are locked.
  • Models and rules: drakmor/ampr_emu (docs/ASSET_PACK_WORKFLOW_EN.md, GPL-3.0), theghostonline/PS5-LZ4-Compression and danthespal/MkPFS.CSharp.
  • Ideas and knowledge: exFAT2AMPR by V-10 (GitHub, GPL-3.0 with additional terms, “Made by V-10”): the list that “Automatic” leaves loose, the recording for profile creation (its structure and constants follow his port of ampr_pack_profile.py) and the upkeep of the game plugins with their table of checksums.

Deleting games & backups

Every game card has Delete, and so does every entry in the Backups tab.

  • Installed games are uninstalled by the console itself – as with “Delete” in the menu, including updates and add-ons.
  • Games from ShadowMountPlus are unregistered first; then the image or the folder is deleted.
  • The app's backups (copies and conversions) are deleted together with their checksum file.
  1. Tap Delete: the window shows exactly what will go.
  2. Tick “I understand: deleting is final”.
  3. Press Delete for good twice (the first click asks “Really?”).
  4. A progress bar with a percentage shows how far it has got.
Your saved data is always kept. A running game is never deleted.
10

Play time

When you played, for how long and how warm the console got: totals for today, 7 and 30 days, the last 14 days as bars, the most played games and the recent sessions with peak temperatures. Can be saved as a spreadsheet (CSV).

11

Back up saved data

Copies the saved data as the console stores it – encrypted, without opening or changing anything – to a USB stick, a disk or the internal SSD (PS5-Sicherung/Spielstaende/<Datum>). Every file is verified; “Verify” reads a backup again later.

Restore works for individual games: the app first backs up the current state, writes all new files next to the old ones first, verifies them and only then replaces the old ones.

Backing up and restoring only happen when no game is running – not even a paused one. Backups from another console cannot be restored.

Per user, split into PS5 games, PS5 apps, PS4 games and PS4 apps. “Delete” (two clicks) removes the saved games of one title; the app backs up the current state first and lets you put it back.

12

Packages

Finds .pkg files on USB drives, disks and in console storage (folder pkg) and shows the picture, name, title ID, version, type and size.

  • Install… – the console installs the package itself; the app provides it and shows the progress. Beforehand, a plan lists what could get in the way.
  • Add to queue – puts packages into a list that is installed one after the other (each with the console’s normal installation). “Add all packages of this title” lines up the game, its updates and add-ons in the right order. A package the console refuses (already installed, game missing) is skipped with the reason; a failure halts the queue (“Continue”, “Retry”). The queue only lasts while the app is running.
  • Split… – splits large packages into parts for FAT32 sticks (up to 4 GB per file) or discs; the original stays unchanged.
  • Install from the PC – choose a .pkg on the computer running the browser, or drag it onto the card; it is sent in pieces while the installation runs and is not stored on the console. The page must stay open meanwhile.
An aborted installation attempt can leave space reserved. You free it again on the console, in the download list, with “Delete”.
13

Files – the file manager

Viewing the console's folders and downloading files works everywhere. Changing – uploading, new folder, renaming, copying, moving, deleting – only works on the drives and in /data. Everywhere else it says “View only”.

Sorting, selecting, viewing

  • Sorting: Above the list you choose “Name”, “Size” or “Date”; the arrow next to it reverses the direction. Folders are always at the top. The browser remembers the choice.
  • Select all: The box above the list selects all entries of the folder (except links and special files). Half filled means: only some of them are selected.
  • Folder sizes: “Size” on a folder counts how much is inside; “Folder sizes” does this for all folders in the view, one after another. A very large folder is reported with “at least” after about 8 seconds.
  • Viewing: “View” shows pictures (PNG, JPG, GIF, WebP, BMP, ICO) and the beginning of text files (up to 256 KB). Other files can only be downloaded.

Copying & moving

  1. Tick the entries.
  2. Press Copy or Cut.
  3. Go to the destination folder and press Paste here.
  4. A bar shows the percentage, the amount of data and the current file; Cancel removes the started entry from the destination again.

Uploading

Upload chooses one or more files; on a PC you can also drag them onto the list. A bar shows the progress per file.

Protected: nothing is ever overwritten, links are never followed, and in the app's folder (/data/PS5-Cooling-Center) only payloads can be changed – ideal for uploading payloads.
14

Payloads

See and quit running payloads, and start saved ones with one click – from /data/PS5-Cooling-Center/payloads or from the USB stick (root or folder payloads). They are started via the console's payload loader (port 9021).

Profiles: A profile is a named sequence of payloads and pauses that “Run” starts step by step. One can be set as the startup profile; the app then runs it by itself after every start (with protection against endless loops). New payloads can be loaded into the console’s folder with “Import from PC”, also while editing a profile. “Back up profiles” and “Load profiles” exchange profiles as a file.

System & log

Security on the home network

  • The interface has no login: every device on the home network can read and change things.
  • The console does not belong on the open internet – do not set up port forwarding to port 8086.
  • If you only want to use it on the device itself, set the network binding in the settings to 127.0.0.1.
  • The app refuses requests that recognisably come from outside websites (error 403).
